# AI 助手与上下文记忆（V0.13.0）

## 配置

在“设置 → 配置 AI 服务与模型 → 添加服务”选择服务商，填入其 HTTPS API 基础地址和 Key，直接点击“获取上游模型”。此按钮会先保存当前输入，再访问模型列表；不要求先填模型 ID 或先开启 AI。选中模型即保存。服务不提供列表时手填模型 ID 后保存。开启 AI 后进入助手。

名称与协议放在高级配置中。地址应含版本路径，不能填网页或单次聊天接口、账号、密码和 URL 查询参数。模型 Key 由 Android Keystore 加密，绑定服务 ID、地址和协议；更改地址后必须重新填写。最多保存 24 个服务。

## 两个工作区

- **问答 / 写 SQL**：普通聊天、解释当前表、SQL 草稿与建议。可选择表结构、编辑器 SQL，发送前预览并脱敏；不会自动发送数据行。回答中的 SQL 可载入编辑器，仍需手动执行。
- **操作当前表**：同样能问“这是什么表”，模型返回解释或澄清时不调用数据库。明确的操作由模型提出结构化计划，本地验证字段、目标与权限。查询显示在工作台；新增、修改和删除只生成单条预览，确认后提交。

写入必须勾选本次允许写入预览。SQL Server 的 `DROP_TABLE` 是唯一新增的 DDL 能力：仅限当前选择的表，本地生成语句，显示结构与全部数据永久删除的影响，并输入完整表名确认。不是删除筛选结果，不提供撤销；不接受模型任意 SQL、其它服务器或其它表目标。其它引擎当前没有 AI 整表删除。AI 表操作目前针对关系型工作台，NoSQL 的新增编辑通过各自原生页面完成。

## 记忆

文字问答以 AES-GCM 加密保存在设备的 noBackupFilesDir，密钥由 Android Keystore 管理。按服务 ID、协议地址、模型、连接、库、表和工作区分别保存。重启或返回同一上下文后可继续问；切换目标不会混用旧对话。“新建对话”删除当前记录；不影响其它上下文。

每个上下文最多 16 个完整问答回合、64000 字符，本机最多 50 个上下文；超限淘汰旧记录。每次发给上游最多最近 8 个完整回合，和本次内容合计不超过 24000 字符。预览中脱敏后的内容才会进入后续记忆。记录加载失败会阻止覆盖，需明确清空后开始；保存失败会提示。

记忆保存问答和“尚未确认”的操作描述，**不保存可执行令牌，不形成离线任务或自动重放队列**。旧消息不代表新的写入授权或操作成功。查询结果不会自动回传模型。记忆仅在本机，不提供跨设备云同步；卸载或系统密钥丢失后可能无法恢复。

## 接口范围

| 协议 | 模型列表 | 文本生成 | 认证 |
|---|---|---|---|
| OpenAI 兼容 | /models | /chat/completions | Bearer |
| Anthropic | /models | /messages | x-api-key |
| Gemini | /models | /models/{id}:generateContent | x-goog-api-key |

预设：OpenAI、Claude、Gemini、DeepSeek、通义千问、豆包、智谱、Kimi、MiniMax、硅基流动、百度千帆、腾讯混元、Grok、OpenRouter、Groq、Mistral、Together、NVIDIA NIM、Perplexity。预设不是逐供应商实测；以用户账号对应的地区、普通 API / Coding Plan 地址为准。

尚无 AWS Bedrock / Vertex IAM、Azure 专有认证、Responses-only、音视频、工具调用与流式输出。外部 AI 可按连接禁止；数据库基础功能不依赖 AI。仅访问固定 HTTPS 上游，拒绝重定向转发密钥；不内置开发者密钥。测试使用本机合成 HTTPS 上游，不冒充真实收费模型验证。
