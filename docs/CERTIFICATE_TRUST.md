# IP、自签名证书与服务器身份

V0.7.2 / versionCode 11 的九种网络数据库共用以下流程。SQLite 为本地文件，不使用 TLS。这不是对未接入数据库或所有服务端版本的兼容声明。

1. 填写连接名称、引擎、服务器地址、端口、用户名，并勾选已获准访问。获取证书不需要密码，目标库可留空。
2. 在表单直接可见的「连接安全」卡片点击「获取并核对服务器证书」。扫描遇到证书校验失败会自动定位此卡片，无需展开高级设置。客户端使用该引擎的真实握手协议，在取得证书后主动中止 TLS；不登录、不读取数据库列表。网络、旧 TLS 协议或明文端口问题可能导致无法取得证书。
3. 通过服务器管理员等独立渠道取得并核对 SHA-256 指纹。界面显示的主体和签发者只是证书自述，不构成身份已获验证的证据。
4. 核对后勾选确认，点击「信任并保存到此连接」。此例外用具体叶证书指纹替代 CA 链与地址匹配校验，适用于默认自签名证书、内部证书或通过 IP 连接的场景。仍要求加密、相同证书及有效期；不接受过期或尚未生效证书。
5. 输入密码，手动点击扫描或连接。确认动作不会自动重试认证。扫描结果选择目标后可保存完整配置。若保存失败会提示，当前页面的选择仍可使用，但不保证下次启动保留。

「证书详情与 CA 设置」仅收纳指纹详情、CA 导入与恢复操作。系统 CA 是默认设置；使用内部 CA 且证书地址正确时，也可直接导入有效 X.509 CA。恢复系统 CA 会移除当前草稿的指纹信任，点击「保存配置」持久化该撤销。若只保存了证书、尚未填写目标库，当前表单的保存按钮仍要求库名；可返回连接列表删除该连接，立即移除它的持久信任记录，再新建连接。修改服务器、端口或引擎以及复制连接会清除指纹信任；数据库或账号变化不改变同一服务器证书身份。信任记录含连接 ID、引擎、地址、端口、指纹和确认时间，无密码、私钥。

证书变化后旧指纹不会自动更新，也不会回退到系统 CA 或明文。界面提示检查证书；重新获取会显示变更警告，须核对更换原因及新指纹。SQL Server 自动生成的证书可能在实例重启后变化。未配置 TLS 的 Redis、MongoDB、Elasticsearch 等服务需要先启用服务端 TLS；本次不增加明文模式。Windows 集成认证、旧 TLS 协议和 IPv6 仍不在本次范围。

实现采用共享 TrustManager，在默认模式检查 CA + SAN，在指纹模式检查叶证书 SHA-256 和有效期。MariaDB/MySQL 的身份校验移动到握手内；PostgreSQL、MongoDB、HTTPS 仅在显式指纹模式下替代驱动附加的域名匹配。预览令牌仅在内存中存在，取消、页面退出、后台或 ViewModel 销毁会注销；晚到结果不能更新连接。TLS 登录取消仍受驱动既有登录/socket 超时限制，不能宣称所有 DNS/握手立即中断。

设置中的“数据库驱动验证”是独立的严格系统 CA 探针，不读取首页连接的信任记录；使用自签名证书的日常扫描和连接请从首页进入。
