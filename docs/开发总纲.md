### 核心约束

APK 安装后从手机直接连接用户授权的数据库，不强制注册，不要求 Root、无障碍、悬浮窗、Termux、Linux 或 KeX。核心功能不强制依赖 Google 服务；此项需纳入测试。

AI 为独立、可关闭功能；没有配置模型服务、模型请求失败或外网不可达时，已具备网络访问条件的数据库查询仍应可用。

直连不是自动穿透内网：生产数据库应通过既有可信内网或用户授权的安全远程接入访问，不为手机访问而把数据库随意暴露到公网。手机无法访问目标网络时，应明确提示网络条件，而不是假报连接成功。

### 首版不做

不做手机数据库服务器、不以网页套壳或强制代理替代原生直连，不做全功能桌面 DBA 替代品；暂不做后台自动写库、云端同步业务数据、账号订阅系统、广告、跨库数据同步、批量生产变更和手机端大模型性能承诺。

## 二、目标使用场景

**现场查询：** 在厂区、仓库或办公室，通过手机查看用户授权的考勤、设备或业务数据，使用筛选与分页定位记录。

**故障排查：** 测试连接，区分域名解析、TCP、TLS、账号、权限与 SQL 错误；对选定且脱敏的 SQL 或错误请求 AI 解释。

**谨慎修正：** 查看单条记录原值，填写变更，预览目标数据库、主键、字段差异与参数，确认后提交并核对结果。

**AI 辅助：** 根据用户选中的真实表结构，将自然语言问题转成指定方言的 SQL 草稿；用户审阅后执行，不让模型直接控制生产数据库。

**临时交付：** 导出经批准的查询结果或 SQL 文件；连接配置备份默认不包含密码。

所有示例使用合成数据。真实员工信息、生产结构、密码、证书私钥和业务记录不能为开发便利进入公共仓库或云端测试材料。

V1.0 的目标锁定为 SQL Server、MySQL、MariaDB、PostgreSQL、SQLite 五种数据库，加上 AI 核心功能。后续引擎均有独立准入门槛，不以图标数量作为完成度。

### 驱动候选与验证原则

候选方案为微软 mssql-jdbc、MariaDB Connector/J 或 MySQL Connector/J、pgJDBC，以及适合授权本地文件工作流的 SQLite 接入方式。Java 支持声明不是本项目 Android 兼容证据。[S8][S9][S10][S11]

微软 JDBC 13.6 的发布说明列出 Android/Conscrypt TLS 登录握手挂起修复，说明具体驱动版本和加密连接真机测试必须记录，不能只验证编译成功。[S8] MariaDB Connector/J 的 MySQL/MariaDB 能力和 LGPL 许可需结合实际打包方式单独评估。[S10]

每个引擎使用“计划中 → 实验性 → 指定组合已验证”状态；“已验证”必须对应服务端版本、驱动版本、Android 版本、认证方式、TLS 条件与功能列表。元数据、编辑、事务、取消、流式读取等能力单独标记；能连上不等于所有能力可用。当前全部能力仍处于计划阶段。

首版 SQL Server 优先 SQL 账号与固定 TCP 端口；Windows 集成认证、Kerberos、复杂企业身份登录和实例自动发现后续单列，不默认宣传支持。

## 四、功能开发范围

### 4.1 连接中心

支持连接新增、编辑、复制、删除、分组、收藏、最近连接与搜索。连接配置包括名称、数据库类型、主机、端口、数据库、Schema、用户名、可选保存的密码、TLS、CA、连接超时和查询超时。

支持生产/测试环境文字标识、默认只读工作模式、连接测试、中文错误解释、一键断开。按连接保存 AI 数据发送策略。不得把明文密码展示在日志、历史、诊断包或连接 URL 中。

分组可由用户自定义，例如“一厂、二厂、光缆厂、测试环境、个人数据库”，这些只是分类示例，不预置真实服务器。

### 4.2 数据库对象浏览

读取用户有权限查看的数据库、Schema、表、视图、字段类型、主外键、索引、约束和备注；支持搜索、刷新和复制对象名称。初期只读取其它对象元信息，不默认执行存储过程或触发器相关操作。

必须区分“无权限”“无记录”“未实现”“连接失效”，不能统一显示空白。数据表页面提供“数据 / 结构 / 索引”入口，危险动作放入独立操作区。

### 4.3 数据浏览

支持横纵滚动、关键列固定、列显隐、字段筛选、排序、分页、单元格复制和单行详情。每页 100 行为可调初始设计值，后续依据实测调整。

大表不整表加载，大字段按需读取；没有可靠排序时说明分页限制，不默认执行全表精确 COUNT。工号和卡号等字符串保留前导零；NULL、空字符串、精确小数、大整数、时间、二进制分别处理。

### 4.4 图形化安全编辑

工作流：选记录 → 查看原值 → 编辑 → 预览旧/新差异、目标库和键值 → 用户确认 → 短事务与并发检查 → 核对结果 → 提交或回滚。

新增、修改、删除分别处理。修改与删除必须有稳定主键或经验证的唯一定位键；无安全定位方式、JOIN 或聚合结果首版只读。标识符通过元数据与方言转义，字段值使用参数绑定，只更新发生变化的字段。

只读是默认工作模式，不是永久禁止用户编辑；解锁写入后仍需要目标确认和权限检查。客户端开关及 SQL 风险提示不能替代数据库最小权限账号。

并发修改、匹配行数异常、触发器副作用应有明确结果。预览行数不是之后执行结果的保证。事务在用户最终确认后才开始，不能持锁等待人或 AI。

断网、超时或取消后无法确定是否已提交，显示“执行结果未知，需要核对”，不自动重试写入。草稿撤销、数据库事务回滚和数据恢复是不同概念；例如 MySQL 部分 DDL 会隐式提交，不能宣称所有操作都能一键回滚。[S14]

### 4.5 SQL 工作台

语法高亮、行号、选择执行、当前语句执行、草稿保存、参数输入、格式化、SQL 收藏、历史搜索、多查询页和结果展示逐步实现。运行前始终能看到目标连接、数据库、Schema 和只读/可写状态。

结果显示列类型、结果集、影响行数、耗时、错误码及中文说明。取消应联动驱动；协程取消或关闭动画不等于服务端已停止。

表浏览器使用受控的方言分页；SQL 编辑器不擅自改写任意 SQL，不统一在末尾拼接 LIMIT。多语句、过程和 DDL 分阶段实现，不简单按分号切割脚本，不把 SQL Server 的批次指令当作普通服务器 SQL 直接发送。

### 4.6 导入、导出与配置备份

基础导出目标为 CSV、JSON 和 SQL 文件保存；后续 CSV 导入提供字段映射、类型预览、错误行报告、批次事务、进度和中断说明。

导出需处理中文、越南语、编码、换行、引号、NULL/空字符串、大整数和 CSV 公式注入风险。结果导出不是完整数据库备份；完整备份还涉及此客户端未覆盖的内容。

文件操作采用 Android 系统文件选择器，让用户授权具体文件，不申请全部文件权限作为捷径。[S7] SQLite 首版操作一致性副本，检查 WAL/文件完整性，编辑后显式另存，不静默覆盖其它应用的活跃数据库。

连接备份默认不含密码；包含凭据的备份另行授权与加密。未经授权不自动向云端上传导出文件。

### 4.7 安全与诊断

应用锁、闲置锁定、敏感结果遮罩、诊断包预览、日志脱敏、危险命令确认、连接级 AI 策略与生产标识纳入设计。

凭据加密密钥用 Android Keystore 保护，密文独立保存在私有存储；Keystore 不等于被攻陷或 Root 设备上运行时明文绝不会泄漏。[S5] 应用不需要 Root，也不承诺依靠 Root 检測就能证明设备安全。

后续增加只读的连接数、锁等待和执行计划查看，不自动杀会话、修改账号权限或调整服务器参数。

## 五、AI 助手设计

### 5.1 功能范围

| 能力 | 输入 | 交付 |
|---|---|---|
| 自然语言生成 SQL | 问题、用户选定结构、方言 | SQL 草稿、参数、解释、假设、引用对象 |
| SQL 解释 | 用户选中的 SQL | 中文说明筛选、关联、聚合和潜在风险 |
| 报错诊断 | 选定 SQL 和脱敏错误 | 原因、排查步骤、修复前后差异 |
| 结构问答 | 已批准表、字段、关系 | 解释结构和关联；不额外扫描整库 |
| 优化建议 | SQL、经批准的执行计划 | 可验证建议、前提和可能副作用 |
| 方言转换 | 源 SQL、目标引擎与版本 | 目标草稿、语义差异与测试提醒 |

使用场景：“根据我选中的考勤表，查询昨天有上班卡、没有下班卡的员工。”AI 必须基于实际字段，缺少班次、跨日和时区口径时说明并要求补充，不能虚构表名、字段或业务规则。

“数舟 AI 助手”作为功能名即可，不再另外引入复杂的子品牌。

### 5.2 交互流程

用户问题 → 选择连接/数据库/表 → 预览要发送的上下文 → 脱敏与策略检查 → 调用所选模型服务 → 收到 SQL 草稿与解释 → 本地风险检查 → 用户送入编辑器并审阅 → 用户执行。

默认不发送数据行、密码、完整连接串或整库结构。表名、字段注释、SQL 常量、错误、执行计划也可能敏感，全部纳入预览和策略控制。结果要送回 AI 分析时，再次选择与批准。

上下文按 connectionId、数据库、Schema 指纹和版本隔离；切库、改 SQL、改参数、改端点或结构变化会使旧批准失效。

### 5.3 执行边界

首版 AI 不自主调用数据库工具，不直接执行读写语句，更不自动执行 DELETE、DROP、ALTER 或服务器管理命令。模型只能提出草稿与建议；最终执行经过与手写 SQL 相同的权限、风险和确认流程。

数据库注释、记录值、外部 SQL 和模型结果都当作不可信内容，不能升级为指令。后续只读 Agent 也必须使用最小权限、结果/预算上限、工具白名单与人工批准；提示词本身不是安全隔离。[S13]

优化建议涉及真实执行、索引或 ANALYZE 时必须单独提示和批准，不能为了生成执行计划而静默运行任意 SQL。

### 5.4 服务接入与成本

通过 AI Provider Adapter 区分原生接口、经验证的兼容接口与自托管接口。服务地址、模型、认证、超时、上下文限额和可选预算可配置；不把某个“当前最新模型”写死在 APK。

可对接用户已有 New API 服务，但需分别测试请求路径、模型列表、流式格式、结构化输出和错误响应，不承诺所有兼容接口可无差别替换。

关闭 AI 不影响数据库功能。客户端不内置开发者统一付费密钥；用户自带服务或使用企业服务。ChatGPT 与 API 平台计费分开，不能把开发 Codex 的套餐默认当作应用模型调用额度。[S12]

异常包括认证失败、限流、超时、模型不可用和流式中断，应保留草稿、说明原因、允许用户重试模型请求，但不能因此重放数据库写入。

## 六、界面与体验

顶层导航建议为“连接 / 工作台 / AI 助手 / 收藏 / 设置”。对象浏览属于连接工作区。手机竖屏以单栏和整行详情为主，横屏及平板后续提供更宽的结果区和双栏浏览。

| 页面 | 主要内容 |
|---|---|
| 连接 | 最近连接、分组、搜索、新增、状态与环境标签 |
| 对象浏览 | 库/Schema/表、搜索、数据/结构/索引切换 |
| 工作台 | SQL 编辑器、执行/取消、参数、结果、多查询页 |
| AI 助手 | 当前上下文、问题输入、生成草稿、解释、风险和发送预览 |
| 收藏 | 常用 SQL、按连接分类、备注和搜索 |
| 设置 | 外观、语言、安全、模型服务、导入导出、更新与诊断 |

视觉方向为简洁、专业、清晰；支持明暗主题。舟/帆与数据关系可以作为未来图标概念，但本包没有生成或交付 Logo。

危险操作不能与复制/刷新放在容易误触的相同位置。生产/测试、成功/失败不能只靠颜色区分。字体放大、TalkBack、外接键盘和中文输入应进入验收；这些是可访问性支持，不是要求启用无障碍服务控制手机。

## 七、技术架构

建议 Kotlin + Jetpack Compose + ViewModel + Coroutines/Flow，UI 与数据源分层；Android 官方将 Compose 和相应架构实践作为推荐路线。[S4]

```text
原生 UI
  → 业务用例与执行策略
  → 连接/会话/能力接口
  → 数据库驱动
  → 用户数据库

AI 面板
  → 上下文选择与脱敏
  → 模型服务适配器
  → SQL 草稿/建议
  → 原有执行策略（用户确认）
```

SQL、文档、键值和搜索分别使用 SqlConnector、DocumentConnector、KeyValueConnector、SearchConnector，不硬套统一字符串 SQL 接口。

Room 只管理应用自身连接元信息、收藏与配置迁移，不作为远程 SQL 驱动，也不强行管理任意用户 SQLite 文件。迁移设计与测试从第一版加入。[S15]

初期只创建当前版本需要的少量 Gradle 模块；先形成清晰接口，再随着功能增长拆分。建议长期目录如下，不代表本包已经存在这些源码：

```text
datasail-android/

├── core/
│   ├── model/
│   ├── database/
│   ├── security/
│   └── storage/
├── drivers/
│   ├── sqlserver/
│   ├── mysql/

│   └── sqlite/
├── features/
├── ai/

```

数据库 I/O 使用有界后台执行；显式释放游标、结果集、Statement、Connection 和文件流。同一会话按顺序执行，网络变化使旧会话失效，不将写请求放入离线队列。结果缓存有上限，不能通过常驻所有连接掩盖生命周期问题。

工具链在初始化时依据官方兼容关系选择稳定组合，并锁定 JDK、AGP、Gradle、Kotlin、Compose、SDK 和驱动版本。最低 Android 8.0 是目标，不得因依赖报错静默提高到 Android 12；确有冲突必须记录取舍。

## 八、Codex 云端开发流程

### 第一步：创建仓库并提交规划

创建建议名为 datasail-android 的 GitHub 仓库，把本规划包内部的 README.md、AGENTS.md、docs/、prompts/、templates/ 等放到仓库根目录。此时没有 Android 工程是正常状态，首次任务负责生成。

没有已确认的发布主体或仓库身份时，com.example.datasail 仅作技术验证占位；正式包名列入发布前待办，不能猜一个 GitHub 账号填进去。

### 第二步：准备与发布云环境

当前官方流程支持选择 GitHub 仓库、准备并测试依赖环境、发布环境、启动任务，以及审查后提交或创建 PR。[S1]

Android 工具链通过可复现的环境准备脚本安装或恢复。当前环境文档包含 Install script 与 Start skill；环境配置应与仓库脚本对应，保存的环境状态不能替代 Git 版本管理。[S2]

先检测 SDK、JDK、磁盘、KVM/模拟器、Docker 和授权测试网络条件；不默认云端具备 Android 模拟器或能访问公司数据库。数据库原生 TCP 可达性与 HTTPS 域名白名单是不同问题。

### 第三步：执行 V0.1.0 技术验证

将 prompts/00_首次创建项目.md 作为第一次任务，只做原生骨架、真实构建、能力接口、驱动验证页、SQL Server/MySQL 连接探针及测试证据。AI 仅预留接口，不一次实现完整路线图。

先证明能构建、能安装、能在真实 Android 运行时安全登录数据库，再完善大量界面。

### 第四步：按小任务持续开发

推荐流程：Issue → 功能分支 → Codex 实现 → 自动检查 → 审阅 PR → 合并 → 测试 APK → 真机反馈 → 修复 → Tag 与发布候选。

每个任务写明目标版本、基线、用户路径、不改范围、验收条件和实际测试环境。AGENTS.md 保留长期规范；官方支持项目级指令按目录发现与覆盖，不应只依赖上一次聊天记忆。[S3]

分支示例为 feature/v0.2-sqlserver-browser、fix/v0.2.1-query-cancel；主分支始终保持可构建。公共接口、根构建配置与版本号由一个任务协调，接口稳定后再并行拆功能。

### 第五步：分层测试与真实交付

Codex 执行可用的静态检查、单元测试与构建；CI 执行重复构建和合适的集成测试；Android 11 真机验证连接、输入法、触控、弱网、进程重建、Release/R8 和覆盖升级。

GitHub Actions 可在具备相应 Linux/Docker 条件的运行器使用数据库服务容器，具体镜像、资源和许可需另行确认。[S16] 不把任意云环境都假定为同一配置。

报告分别记录“构建通过、单元测试通过、数据库集成通过、Android 实连通过、真机通过”，未执行项明确写未执行。没有 APK 就写未交付，不编造链接或把源码 ZIP 当作安装包。

## 十、版本目录、升级与发布

采用“一份活跃源码 + 每版不可变完整归档”。不要让 Codex 每轮从头重建新项目，也不要覆盖旧版源码快照。

```text
versions/
└── V0.2.0/
    ├── source/                  完整可构建源码
    ├── apk/                     该版本真实 APK
    ├── docs/                    该版本文档与兼容矩阵
    ├── 更新说明.md
    ├── 测试报告.md
    ├── 已知问题.md
    ├── manifest.json
    └── SHA256SUMS
```

source 包含 Gradle Wrapper、构建配置、测试、脚本和示例配置；排除 .git、缓存、build、密钥、真实数据及 versions 自身。历史目录不参与 Gradle 编译，完整版本 ZIP 可作为 Release 附件，不必让 Git 重复保存所有历史大文件。

versionName 按功能/修订管理，versionCode 每次发行递增；记录 Git SHA、工具链、驱动、签名指纹、产物校验值和实际测试范围。内部连续升级的测试包也需要稳定签名策略；云端临时 Debug 密钥不应被当作正式升级方案。[S6]

签名私钥只在受保护发布流程使用，不放仓库、不交普通 PR 和开发任务。初期通过用户下载 APK 并由系统安装器确认更新；后续应用内检查更新仍需可信来源和安装确认，不做静默安装。

应用升级只迁移应用自己的配置，不自动修改远端业务结构。Room 迁移及跨版本覆盖安装必须测试，不能通过清空数据库解决迁移失败。[S15] 密钥失效时要求重新认证，不静默删除全部配置。回退优先准备基于稳定实现的更高构建号修复包，并验证本地配置兼容，而非保证老 APK 可随便降级。

## 十一、测试与验收

测试层次为纯逻辑单测、Android 仪器/UI、真实数据库集成和 Release 真机。合成数据覆盖中文、越南语、前导零、NULL、大整数、精确小数、复合主键、无主键、并发更新、大表与大字段。

关键异常覆盖错误证书、错误账号、权限不足、取消失败、锁等待、提交期间断网、进程重建、输入法遮挡、导出中断、存储不足和升级迁移。

AI 覆盖虚构字段、错方言、恶意表注释、切库后复用批准、跨域泄露认证、未经批准取数或写入等用例；记录模型、端点、参数与 Schema 版本。语法正确不等于业务结果正确。

性能先建立设备与数据集基线，再定峰值内存、滚动与连接资源回收目标；不凭空承诺固定 MB、毫秒或“零 Bug”。

任何未经批准写入、错库执行、密码泄漏、默认跳过证书校验、升级丢配置、类型破坏或无主键误改，都阻断正式发布。

## 十二、首次启动与后续交付

第一次只提交 V0.1.0 指令，具体内容见 prompts/00_首次创建项目.md。后续功能使用 01_功能迭代模板.md，故障使用 02_Bug修复模板.md，发布候选使用 03_发布与升级模板.md。

每次回复用中文说明：完成内容、变更文件、实际测试命令与结果、未验证项和风险、版本/构建号、真实 APK 与完整源码归档路径，以及下一项最小开发任务。

本包提供规划、规范和任务模板，不执行 GitHub 创建、不提交代码、不发布 Release、不提供已完成 APK。建议现在从“数舟 V0.1.0：原生工程与驱动技术验证”开始实施。

技术依据及查询日期见同目录 SOURCES.md。文中 [S1]—[S16] 对应该文件；设计目标不等于平台保证或项目实测结果。
