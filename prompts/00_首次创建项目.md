# 数舟 · DataSail：首次交给 Codex Cloud 的任务

请在当前 GitHub 仓库从零创建“数舟 / DataSail”的原生 Android 项目。
本次只完成 V0.1.0 技术验证版，不要一次实现整个产品路线图。

## 一、先读取项目规范

依次阅读根目录 AGENTS.md、README.md，以及 docs/开发总纲.md、docs/PROJECT_IDENTITY.md、docs/ARCHITECTURE.md、docs/DRIVER_MATRIX.md、docs/ROADMAP.md、docs/CODEX_CLOUD.md。
这些文件定义目标，不代表已有源码、已实现功能或已验证兼容性。

检查当前分支、仓库文件和未提交修改，保留已有有效工作；若已有可用工程，应在其基础上增量实现，禁止无理由重建项目。

## 二、命名与硬约束

- 中文应用名称：数舟；英文名称和项目名：DataSail。
- 仓库建议名：datasail-android；不要擅自操作远端仓库重命名。
- 正式 applicationId 优先沿用仓库中已确认的值。没有确认信息时可使用 com.example.datasail 作为技术验证占位，并记录首次发行前待确认；不得虚构用户 GitHub 账号或域名。
- 中文、免费开源、APK 直接连接用户授权数据库；不是 WebView 套壳，不要求部署强制数据库代理。
- 不依赖 Root、无障碍、悬浮窗、Termux、Linux/KeX。
- Android 11 为重点；Android 8.0/API26 是拟定最低版本，遇到兼容问题必须报告，不能静默提高。
- AI 仅预留清晰的独立接口，本轮不实现模型自动操作数据库；未配置 AI 不影响数据库功能。

## 三、先验证环境

检查 JDK、Android SDK/Command-line Tools、Gradle、可写磁盘与内存、KVM/模拟器、Docker 和授权测试端点条件。
查阅当前官方兼容关系，选择并锁定稳定的 JDK、AGP、Gradle、Kotlin、Compose、SDK 与驱动组合；记录实际版本与来源，不使用浮动依赖。
环境脚本应可重复执行，放入 scripts/，不要只依赖一次性的云端环境状态。

## 四、本次实现范围

1. 创建 Kotlin + Jetpack Compose 工程、Gradle Wrapper、版本目录、基础单测和真实可执行的 CI 构建配置。
2. 实现中文基础导航和数据库驱动验证页；未实现入口明确禁用，不展示假的连接成功或业务数据。
3. 建立数据库类型与值模型、连接/执行状态、错误分类、能力接口、凭据隔离、TLS 策略和脱敏日志。
4. 优先验证 SQL Server，再验证 MySQL。连接配置由测试时输入，不把密码硬编码。
5. 探针验证连接/断开、TLS 与证书校验、SELECT 1、Unicode、NULL、精确小数、超时和取消；能力不足时清楚报告。
6. 只使用明确授权的隔离测试库和合成数据。无服务器时提供测试/CI 方案并标记未执行，不扫描企业网络，不使用生产账号。
7. 所有数据库 I/O 在有界后台执行，取消联动驱动；成功、失败与结果未知分开，不自动重放写入。
8. 执行实际可用的静态检查、单元测试和 assembleDebug，生成真实 Debug APK；准备 Release/R8 验证路径，不以忽略全部警告代替修复。
9. 更新真实兼容矩阵：driver artifact/版本/许可、服务端版本、Android/ABI、认证、TLS、已测能力与未验证项。
10. 在版本交付时生成 versions/V0.1.0/ 完整独立归档：source/、apk/、docs/、更新说明.md、测试报告.md、已知问题.md、manifest.json、SHA256SUMS。排除密钥、真实数据、缓存、build、.git 和 versions 自身，保留此前历史。

## 五、本轮不做

不做其它数据库、完整数据编辑器、完整 AI、账户同步、收费、广告或自动写库。
不上传密钥，不关闭 TLS 校验修复连接，不把 JVM/Mock 测试冒充 Android 实连测试，不用空文件充当 APK。
不在普通开发任务读取正式签名密钥，不在未经授权的情况下公开发布版本。

## 六、遇到阻塞时

继续完成其余可执行部分。记录具体错误、已经尝试的方案、影响范围和下一步验证步骤。
构建、安装、真实数据库连接、Android 实连、真机验收分别报告；没有执行的项目必须写“未执行”，不得总结为“全部通过”。

## 七、最终交付格式

请用中文提供：
完成内容；主要变更文件；工具链实际版本；实际测试命令、退出状态与结果；驱动兼容矩阵；未验证项与风险；版本/构建号；APK 与完整源码归档的真实路径；下一项最小开发任务。

本次验收重点：数舟工程可以构建，产物真实，驱动结论有证据，未完成部分透明；不是追求一次性堆满功能。
